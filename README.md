# chronofit

**「実際にどれだけかかったか」を勝手に測り、そこから予定を組む。**

手動のタイマー操作を一切要求しない時間計測と、その実測から所要時間を見積もって
スケジュールへ落とすための道具立て。Windows で動く。**依存パッケージなし**（標準ライブラリのみ）。

## 何が違うのか

時間計測ツールは山ほどあるが、どれも「合計何時間やったか」しか返さない。ここが欲しいのは
**`(科目 × 種別 × 何本目)` で引ける所要時間**である。過去問は1本目に6時間かかっても
5本目は1.5時間で終わる。この逓減を実測から学習しない限り、見積もりはいつまでも勘のままになる。

もう一つ。従来の見積もりは大きなバッファを置き、その**バッファの中にだらけた時間が混ざっている**。
chronofit は在席時間（`wall`）と実際に入力があった時間（`net`）を分けて持つので、
「だらけ率」を科目の重さから切り離して、実測された定数として扱える。

```
必要な暦時間 = est_net(科目, 種別, 何本目) ÷ slack_ratio(日タイプ)
```

## 設計原則

**人間を計測ループから外す。** 開始/停止のボタンを押させる仕組みは続かない（[docs/DESIGN.md](docs/DESIGN.md) §0
に3回分の実測記録がある）。人間の仕事は、1日1回まとめて離席ブロックにラベルを付ける数タップだけ。

## 計測の4層

| 層 | 中身 | 人間の操作 |
|---|---|---|
| L0 端末イベント | 前景ウィンドウ・タイトル・入力アイドル・スリープ | **ゼロ** |
| L1 既存の痕跡 | ブラウザ履歴・git コミット・音声メモ | **ゼロ**（回収するだけ） |
| L2 オフPC | L0 のギャップに後追いでラベル | 1日数タップ |
| L3 所要時間DB | タスクインスタンス単位の net / wall | 導出 |

入力アイドルを見るのが要点。前景が PDF のままでも入力が無ければ在席として数えないので、
「画面を出したまま別のことをしていた時間」が作業時間に混ざらない。

## 使い方

```bash
python -m chronofit collect     # 端末イベントの収集（常駐。ログオン時に自動起動させる）
python -m chronofit snapshot    # ブラウザ履歴を退避（Chromium は勝手に刈るので日次で）
python -m chronofit status      # 収集できているかの確認
python -m chronofit backfill-clockify <csv>   # 過去の Clockify エクスポートを取り込む
```

`snapshot` は日次で回すこと。実測で Vivaldi の履歴は **16日分しか残っていなかった**。
写しておかないと過去の接点ログは取り返しがつかない形で消える。

## データの置き場所

| 中身 | 場所 | 公開 |
|---|---|---|
| ロジック | このリポジトリ | public |
| 生イベント（ウィンドウタイトル込み） | `%LOCALAPPDATA%\chronofit\` | **git に入れない** |
| 個人設定・日次ロールアップ | 利用側の private リポジトリ | private |

生イベントは「今まで開いた全ウィンドウの題名」なので、private リポジトリにも置かない。
`CHRONOFIT_HOME` で置き場所を上書きできる。

このリポジトリには個人固有の定数（科目名・容量・分類ルール）を一切置かない。
それらは利用側から設定として注入する。
