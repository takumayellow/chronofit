# plan — 実測から見積もって予定を組む

## このスキルの立場

見積もりを**勘で書かない**。`chronofit` が測った実績を引いて数字を出す。実績が無い項目は
「実績なし」と明示して仮値を置き、**次にそれを測る対象として記録する**。仮値を実測のように
書かない。

## 手順

### 1. タスクを構造化する

渡されたタスクを `(科目, 種別, 対象, 通し番号)` に分解する。種別は
`過去問 / 参考書 / 講義資料読み / レポート / 実装 / 暗記` を既定とする。

粒度の目安は **1インスタンス = 1〜6時間**。「応用数学Bをやる」は分解が足りない。
「応用数学B 過去問 2024年度期末（3本目）」まで落とす。

### 2. 実測DBを引く

`python -m chronofit status` でデータの厚みを先に確認し、次の順で見積もり値を決める:

1. **同じ (科目, 種別) の実測がある** → 通し番号に対する逓減を実測から外挿する
2. **同じ種別の他科目の実測がある** → その曲線を科目係数で調整して流用
3. **どちらも無い** → 仮値を置き、**`実績なし(仮)` と明記**する

見積もりは `net`（実際に手が動いた時間）で出す。

### 3. 暦時間に直す

```
必要な暦時間 = est_net ÷ slack_ratio(日タイプ)
```

`slack_ratio` は実測された定数（在席時間に対する入力ありの割合）。日タイプ（平日夜／休日／
出社日）ごとに違う。**勘でバッファを積まない。** バッファはこの比に既に入っている。

### 4. 使える時間へ割り付ける

- 容量は**暦時間**で持つ。カレンダーの既存予定・出社日・固定の拘束を先に引く。
- 締切のあるものから earliest-fit。締切は Jira の due date を正とする。
- 1日に詰め込みすぎない。実測の日次上限を超える配置はしない。

### 5. 出力

必ずこの3つを添える:

- **見積もりの根拠** — 各項目が「実測 n件から」なのか「仮値」なのかを1行で
- **入りきらなかったもの** — 容量を超えて落とした分を隠さず列挙する
- **次に測るべきもの** — 実績が無くて仮値になった項目

## やってはいけないこと

- 実績が無いのに、あるかのような具体的な数字を出す
- 容量に入らないタスクを黙って落とす（落とすなら明示して、要選の判断をユーザーに返す）
- 時刻単位まで割り付けて満足する。**遂行されない粒度の計画は作っても意味がない**
  — 実測で「カレンダー通りには全く動けない」ことが分かっている。既定は**週単位のゴール**、
  時刻ブロックは本人が明示的に望んだときだけ。

## 週次レビュー（このスキルの相方）

計画は立てた時点では価値が無い。週に一度、15分:

1. `python -m chronofit status` で先週の実績を出す
2. 計画とのズレを見る。**ズレたら計画を直す。自分を責める材料にしない**
3. 見積もりが外れた項目は実測値でDBを更新する
4. 次の週のゴールを3つだけ決める
